# Как мы работаем

Полные правила — в [CONTRIBUTING.md](https://github.com/Apophis142/edu-doc-agent/blob/main/CONTRIBUTING.md)
в корне репозитория. Здесь — краткая выжимка.

## Ключевое

- `main` защищена: прямые пуши запрещены, только через PR.
- Одна задача — одна ветка, живёт 1–5 дней. Именование:
  `feat/12-docx-parser`, `fix/31-wrong-credits-sum`, `docs/18-architecture-page`,
  `exp/20-llm-benchmark`, `chore/9-ci-setup`.
- Заголовки PR — по Conventional Commits: `feat(parsing): извлечение таблиц из DOCX`.
- Слияние — только squash merge.
- После approve и зелёного CI автор сам нажимает **Squash and merge**.

## Definition of Done

- CI зелёный, PR одобрен одним ревьюером.
- На новую логику есть тесты.
- Если менялось поведение или API — обновлена документация.
- В диффе нет секретов и файлов >1 МБ.

## Локальный цикл

```bash
git switch main && git pull
git switch -c feat/12-docx-parser

# работа
uv run pre-commit run --all-files
uv run pytest
git add . && git commit -m "feat(parsing): каркас парсера"
git push -u origin feat/12-docx-parser
```

## Данные
- Реальные документы ОП — вне репозитория, в облаке команды или локально у разработчика (DATA_DIR в .env).
- В `tests/fixtures/` — только синтетические документы.
- Секреты — только в `.env`, файл в git не попадает.

## Ритм
- Еженедельный созвон 45-60 минут.
- Демо раз в две недели: показываем, что работает сквозь всю систему из main, а не в отдельном ноутбуке.
- Архитектурные решения — короткие ADR в docs/adr/.
