# Как мы работаем

## Ветки и PR

- `main` всегда рабочая, прямые пуши запрещены.
- Одна задача — одна ветка, живёт 1–5 дней.
- Именование: `<тип>/<номер-issue>-<коротко-латиницей>`,
  например `feat/12-docx-parser`.
- Типы: `feat`, `fix`, `exp`, `chore`.
- Заголовки PR — по Conventional Commits: `feat(parsing): извлечение таблиц из DOCX`.
- Слияние — только squash merge. После слияния ветка удаляется автоматически.

## Локальный цикл

```bash
git switch main && git pull
git switch -c feat/12-docx-parser

# ... работа ...

uv run pre-commit run --all-files
uv run pytest
git add . && git commit -m "feat(parsing): каркас парсера"
git push -u origin feat/12-docx-parser
# → открыть PR, указать Closes #12, назначить ревьюера
```

# Definition of Done
- CI зелёный, PR одобрен одним ревьюером.
- На новую логику есть тесты; для экспериментов — описание результатов в PR.
- Если менялось поведение или API — обновлена документация в `docs/`.
- В диффе нет секретов, реальных документов ОП и файлов >1 МБ.

# Секреты и данные
- Ключи API — только в .env, файл в git не попадает.
- Реальные документы ОП — только в закрытой папке команды, в git не кладём.
- В tests/fixtures/ — только синтетические документы.
- Если ключ всё же попал в коммит: немедленно отозвать у провайдера. Удаление файла не поможет — он остаётся в истории.

# Ноутбуки
- `notebooks/NN-фамилия-тема.ipynb`, каждый правит только свои.
- Выводы ячеек вычищает nbstripout автоматически.
- Логика, нужная больше одного раза, переезжает в `src/` отдельным PR.

# Тесты
- `uv run pytest` — юнит-тесты, без настоящей LLM (используется в CI).
- `uv run pytest --run-llm` — тесты, требующие ключа LLM. Локально, вручную.
